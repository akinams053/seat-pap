## 已完成（阶段 7 及细化）

阶段 7 四项决策（详见 [`02-整体计划.md`](02-整体计划.md) §11–§13）均已实现：

1. **带符号口径**：出勤 = 普通行动全部最终值（含惩罚负值）；消费 = 抽奖行动全部最终值取负；可用 = `SUM(value)`。`出勤 − 消费 = 可用` 精确成立。
2. **全局起始日**：`Pap::statisticsStartDate()` 单一来源，设置页可配置（月初对齐），个人页 / 军团页 / API / 抽奖余额统一以此为起点。
3. **API `since`**：clamp 为 `max(since, 起始日)`；`?breakdown=1` 附带三口径，`total_pap` 默认兼容。
4. **抽奖正数异常**：不进公式，只读巡检暴露（见 §2）。

随后细化：个人页顶部「当前可用 PAP（累计）」+ 当月/当年「出勤/消费/入账」breakdown + 出勤/消费双线趋势图；荣誉榜按出勤排并取消周榜；军团类型分布合并为可选月/年且排除抽奖消费；新增独立「军团消费 PAP」卡；排名导出加「累计可用余额」列；清理废弃通知/Slack/Discord 设置。

**真实样本验证**（测试服）：角色买 1 节点未退款 → 个人页/军团排行/军团消费卡/API breakdown 全部显示 出勤10·消费1·可用9·累计余额9，四处一致。

## 2. 数据巡检（回归 / 异常排查用）

阶段 7 上线后或排查异常时，在 SeAT 宿主 `/var/www/seat`（连接约定见 [`04-交接说明.md`](04-交接说明.md)）执行只读核对：

```bash
sudo -u www-data php artisan tinker
```

核对样本：

- 普通行动是否存在最终负值（被扣成负数 → 按决策计入出勤 PAP 惩罚）；
- 抽奖行动是否存在最终正值（异常，应巡检 + 告警）；
- 已退款抽奖是否回到 0；
- `出勤 PAP − 消费 PAP` 是否等于 `SUM(value)`（带符号口径下应恒等）；
- 同一用户多个 alt 是否正确归并到 main character；
- 军团页面「先按军团成员过滤，再主角色归并」是否仍成立。

抽奖正数异常巡检 SQL：

```sql
SELECT * FROM kassie_calendar_paps p
JOIN kassie_calendar_lotteries l ON l.operation_id = p.operation_id
WHERE p.value > 0;
```

### 1. 迁移与表结构

**宿主命令**
```bash
php artisan migrate
php artisan migrate:status | egrep 'widen_pap_value|analytics_enum|create_lottery_tables'
```

三条应为 `Ran`：`widen_pap_value_precision` / `extend_calendar_tags_analytics_enum` / `create_lottery_tables`。

**SQL**
```sql
SHOW COLUMNS FROM kassie_calendar_paps LIKE 'value';              -- decimal(8,2)
SHOW COLUMNS FROM kassie_calendar_pap_adjustments LIKE 'value';   -- decimal(8,2)
SHOW COLUMNS FROM calendar_tags LIKE 'analytics';                 -- 含 'lottery'
SHOW TABLES LIKE 'kassie_calendar_lotter%';                       -- lotteries / _prizes / _nodes
SHOW INDEX FROM kassie_calendar_lotteries;                        -- operation_id 唯一、status、created_by
SHOW INDEX FROM kassie_calendar_lottery_nodes;                    -- (lottery_id,node_number) 唯一
```

> 迁移只扩字段范围、只加 enum 取值，前向安全。可 `SELECT COUNT(*) FROM kassie_calendar_paps;` 对比迁移前后行数不变。

### 2. 创建抽奖

侧边栏出现 **PAP 抽奖**（骰子图标），进 `/calendar/lotteries` 点「创建抽奖」。建议参数：标题 `验证测试`、节点 `5`、单价 `1.00`、每人上限 `3`、≥2 个奖品、先选**不允许重复中奖**。提交后跳详情页，状态 `open`。

**SQL**
```sql
SELECT id, operation_id, title, node_count, node_price, max_nodes_per_user,
       allow_repeat_winners, status, created_by_character_id
FROM kassie_calendar_lotteries ORDER BY id DESC LIMIT 1;   -- 记 id=:lottery_id, operation_id=:op_id

SELECT COUNT(*) FROM kassie_calendar_lottery_nodes WHERE lottery_id = :lottery_id;  -- = node_count，user_id/purchased_at 全 NULL
SELECT sort_order, name FROM kassie_calendar_lottery_prizes WHERE lottery_id = :lottery_id ORDER BY sort_order;

SELECT id, name, quantifier, analytics FROM calendar_tags WHERE analytics = 'lottery';  -- 一条，quantifier=0.00
SELECT * FROM calendar_tag_operation WHERE operation_id = :op_id;                        -- 绑定 lottery tag
```

### 3. 购买节点与扣费

> 用一个普通成员账号（已有 ≥5 PAP、起始日之后）登录进详情页。

**SQL**（购买前基线）
```sql
SELECT COALESCE(SUM(value),0) AS available_pap
FROM kassie_calendar_paps
WHERE join_time >= '2026-01-01'
  AND character_id IN ( /* 该用户全部 character_id */ );
SELECT character_id FROM refresh_tokens WHERE user_id = :user_id;
```

购买区输入 `2` 购买，成功后整页刷新、2 个节点变绿。

**SQL**（扣费正确性）
```sql
SELECT operation_id, character_id, value, reason, created_by_character_id
FROM kassie_calendar_pap_adjustments WHERE operation_id = :op_id ORDER BY id DESC LIMIT 1;  -- value = -2.00

SELECT operation_id, character_id, value, join_time FROM kassie_calendar_paps WHERE operation_id = :op_id;  -- value 回写 -2.00

SELECT node_number, user_id, character_id, pap_adjustment_id, purchased_at
FROM kassie_calendar_lottery_nodes WHERE lottery_id = :lottery_id AND user_id IS NOT NULL;
```

要点：`paps.value` 为负且 = 该用户该 op 下所有 adjustment 之和（base=0）；购买节点 `pap_adjustment_id` 指向那条负数记录；可用 PAP 减少 2.00。

校验项（可选）：超每人上限 → 「超过每人上限」；超剩余 → 「剩余节点不足」；余额不足 → 「可用 PAP 不足」。

并发购买核心 SQL（已实测 30/30）：
```sql
SELECT COUNT(*) FROM kassie_calendar_lottery_nodes
WHERE lottery_id = :lottery_id AND purchased_at IS NOT NULL AND refunded_at IS NULL AND voided_at IS NULL;
SELECT COUNT(DISTINCT node_number) FROM kassie_calendar_lottery_nodes
WHERE lottery_id = :lottery_id AND purchased_at IS NOT NULL AND refunded_at IS NULL AND voided_at IS NULL;
SELECT COUNT(*) AS cnt, COALESCE(SUM(value),0) AS sum FROM kassie_calendar_pap_adjustments
WHERE operation_id = :op_id AND character_id IN (/* 并发测试角色 */);
```

### 4. 售完手动开奖

买满 5 个 → `sold_out` → FC / 管理员可见 **开奖** 按钮 → 点开。

**SQL**
```sql
SELECT status, drawn_by_character_id, drawn_at FROM kassie_calendar_lotteries WHERE id = :lottery_id;  -- drawn
SELECT sort_order, name, winner_node_number, winner_user_id, winner_character_id, drawn_at
FROM kassie_calendar_lottery_prizes WHERE lottery_id = :lottery_id ORDER BY sort_order;
SELECT draw_log FROM kassie_calendar_lotteries WHERE id = :lottery_id;   -- draw_mode=sold_out, rounds[]
```

不允许重复中奖时两奖 `winner_node_number` / `winner_user_id` 应不同（候选耗尽时该奖 winner 为 NULL）。幂等：对已 `drawn` 再 POST `draw` 应被拒。

### 5. 提前开奖

另建一期（节点 `3`、单价 `1`、上限 `3`、2 奖品、勾选允许重复中奖），只买 **2** 个（留 1 不卖）保持 `open`。详情页出现黄色 **提前开奖** 按钮（仅 `open` 且 `sold_count > 0` 显示），确认框提示「未售节点将作废」。

**SQL**
```sql
SELECT status, JSON_EXTRACT(draw_log, '$.draw_mode') AS draw_mode
FROM kassie_calendar_lotteries WHERE id = :lottery_id3;   -- drawn, "early"
SELECT node_number, purchased_at, voided_at FROM kassie_calendar_lottery_nodes
WHERE lottery_id = :lottery_id3 ORDER BY node_number;     -- 已购 voided_at 空；未售 voided_at 非空
SELECT sort_order, name, winner_node_number, winner_character_id
FROM kassie_calendar_lottery_prizes WHERE lottery_id = :lottery_id3 ORDER BY sort_order;  -- 中奖只落已售节点
```

要点：未售节点 `voided_at` 非空且不出现在任何中奖节点；一个都没售出时尝试提前开奖应被拒；`paps.value` 不因开奖改变。

### 6. 取消与退款

另建一期、买几个、保持 `open`/`sold_out` 后点「取消并退款」。

**SQL**
```sql
SELECT status FROM kassie_calendar_lotteries WHERE id = :lottery_id2;  -- cancelled
SELECT character_id, value, reason, created_by_character_id
FROM kassie_calendar_pap_adjustments WHERE operation_id = :op_id2 ORDER BY id DESC;  -- 每购买者 +正数退款
SELECT character_id, value FROM kassie_calendar_paps WHERE operation_id = :op_id2;   -- 净额回 0
SELECT COUNT(*) FROM kassie_calendar_lottery_nodes WHERE lottery_id = :lottery_id2 AND refunded_at IS NOT NULL;
```

要点：退款 = 已购节点数 × 单价；`paps.value` 回 0；可用 PAP 恢复购买前水平。幂等：对已 `cancelled` 再 POST `cancel` 应被拒、不产生第二条退款。

### 7. 行动审查友好化

进 `/calendar/audit`：抽奖行动标题前有 **抽奖** 徽标；「单 PAP」列显示 **—**；「总额」为负时显示 **消费 PAP xxx**；明细弹窗标题有 **查看抽奖详情** 链接；流水能看到购买扣费 /退款；管理员弹窗底部有 **整行动 PAP 清零** 按钮。

**整行动清零**（先用普通 action 验成功路径，再用未终态 lottery action 验拒绝路径）：

**SQL**
```sql
SELECT character_id, value FROM kassie_calendar_paps WHERE operation_id = :op_id3 ORDER BY character_id;  -- 全归 0
SELECT character_id, value, reason, created_by_character_id, created_at
FROM kassie_calendar_pap_adjustments WHERE operation_id = :op_id3 ORDER BY id DESC;  -- 每非 0 成员 +一条反向 adjustment
```

要点：原 `value != 0` 的成员各新增一条反向 adjustment；已是 0 的跳过；再次清零提示「无需清零」不新增；对未终态 lottery action（`open`/`sold_out`）执行应被拒（HTTP 422）。已全额退款的抽奖净额为 0，总额显示 0.00（非「消费 PAP」），属预期。

### 8. 回归检查
