# 01 · 项目说明

> 本文档说明 `seat-pap` 当前**是什么、能做什么、怎么用**，并整合了 FC 日常操作与 PAP 商店对接协议。
> 设计与规划见 [`02-整体计划.md`](02-整体计划.md)；下一步该做什么见 [`03-近期计划.md`](03-近期计划.md)；当前部署状态见 [`04-交接说明.md`](04-交接说明.md)。

## 1. 项目概述

面向 **SeAT 5.x** 的 Calendar / PAP 插件，fork 自 [hermesdj/seat-calendar](https://github.com/hermesdj/seat-calendar)，已移除 Discord / Slack / Mail / 外部通知集成，重新定位为核心 **Calendar / PAP** 插件。

| 项目 | 版本 |
|------|------|
| SeAT | 5.x |
| Laravel | 10.x |
| PHP | 8.1 – 8.4 |

目标部署环境 **Ubuntu 22.04**，宿主 SeAT 根目录 `/var/www/seat`，最终通过 **Packagist** 安装。安装 / 更新命令见仓库根 `README.md`。

## 2. 功能概览

### Operation 管理
- 创建 / 更新 / 取消 / 重新激活 / 关闭 / 删除 operation
- 基于角色（Role）的 operation 可见性控制
- 用户按角色报名（attending / not attending / maybe）
- operation 标签管理（分类、排序、analytics 分轴、quantifier）

### PAP 采集与统计
- FC 通过 ESI 拉取当前 fleet 成员，一键生成 PAP
- PAP 发放后自动更新舰队 MOTD
- **主角色聚合**：所有 alt 的 PAP 自动归并到 main character
- **三口径统计**：**出勤 PAP / 消费 PAP / 当前可用 PAP**（出勤 − 消费 = 可用 恒等），详见 [`02-整体计划.md`](02-整体计划.md)
- **全局 PAP 起始日**：管理员在设置页配置（月初对齐），之前数据保留但不计入统计、排行与消费；个人页 / 军团页 / API / 抽奖余额统一以此为起点
- 角色维度：顶部「当前可用 PAP（累计）」、当月 / 当年「出勤 / 消费 / 入账」breakdown、出勤/消费双线趋势图、本月 / 本年荣誉榜（按出勤排）
- 军团维度：出勤 PAP 月度趋势、出勤 PAP 类型分布（可选月/年）、军团消费 PAP 汇总、排名榜（按出勤排，Excel 导出含出勤/消费/入账/累计可用余额）

### 行动审查（Operation Audit）
- 列出所有已发放 PAP 的**普通出勤行动**与**抽奖结算行动**；商店消费锚不会混入此页
- 支持对单个成员做事后奖励 / 扣除；抽奖结算后的纠错也走这里
- 调整结果实时回写，所有统计页面与外部 API 自动同步
- 完整审计轨迹：操作人（SeAT 用户主角色）、时间、理由

### PAP 超网抽奖（已外移）
- 抽奖玩法运行在**外部独立服务器**；SeAT 不再负责节点、购买、开奖 UI
- 侧边栏 **超网抽奖** 入口携带 JWT（含余额快照）302 跳转外部服务
- 外部服务开奖后调用 `POST /api/calendar/paps/lottery/settle`，SeAT 将整场抽奖结算成一个可审查的 operation
- 设计见 [`05-抽奖外移与PAP银行化设计.md`](05-抽奖外移与PAP银行化设计.md)；对接协议见 [`06-API使用说明.md`](06-API使用说明.md)

### PAP API / 商店跳转
- **读接口**：REST API 供外部服务查询主角色聚合后的当前可用 PAP（读 token 鉴权）
- **抽奖写接口**：`POST /api/calendar/paps/lottery/settle`，开奖后一次性结算整场抽奖（写 token 鉴权）
- **商店预留写接口**：`POST /api/calendar/paps/debit`、`POST /api/calendar/paps/refund`，当前抽奖不调用，保留给未来 PAP 商店
- 侧边栏 **PAP 商店** / **超网抽奖** 入口携带 JWT 跳转，外部用 API Token 验证签名
- 协议见本文 §6，完整字段以 [`06-API使用说明.md`](06-API使用说明.md) 为准

### MOTD 自定义 / 排名显示
- 设置页可自定义舰队 MOTD 各要素颜色与底部签名，提供实时预览
- 排名榜前三名金 / 银 / 铜奖杯，进度条显示相对贡献占比，自动高亮本人主角色

## 4. FC 操作指南

### 4.1 前提条件

1. 角色已在 SeAT 注册并授权以下 ESI scope：
   - `esi-fleets.read_fleet.v1` — 读取舰队成员列表
   - `esi-fleets.write_fleet.v1` — PAP 发放后自动更新舰队 MOTD
2. SeAT 账号拥有 `calendar.create` 权限
3. PAP 发放时必须是舰队的 **fleet boss**

> `write_fleet` scope 不在 SeAT 默认 SSO 列表，需手动添加（命令见仓库根 `README.md` 的 ESI Scope 配置）。缺少它不影响 PAP 发放，仅影响 MOTD 更新。

### 4.2 创建行动

**日历 → 行动 → 创建新行动**，关键字段：

| 字段 | 必填 | 说明 |
|------|------|------|
| 标题 | 是 | 行动名，也是 MOTD 中的舰队名 |
| 角色限制 | 否 | 限制哪些 SeAT 角色可见 / 报名 |
| 重要性 | 是 | 0–5，用于排序 |
| 标签 | 建议 | **量化（quantifier）** 决定本次 PAP 数量（多标签取最大）；**解析轴（analytics）** 决定 PAP 类型 |
| 持续时间 / 时间 | 是 | 起止或仅开始时间 |
| 集结星系 / 信息 | 否 | 自动补全 |
| 舰队指挥 | 是 | 你的角色名 |
| 描述 | 否 | 支持 BBCode |

> 至少勾选一个带量化值的标签，否则 PAP 默认 0。

### 4.3 发放 PAP

行动进行中（或已停止），FC 一栏出现 **PAP 发放** 按钮：

- **首次发放**：确认舰队成员完整后点击，为所有当前成员创建 PAP 记录并更新 MOTD。
- **补发**：再次点击会对比当前舰队与已发放记录，仅为新成员补发，不重复。
- **全员已发放**：提示无需补发，不显示确认按钮。

MOTD 自动更新为彩色通知（舰队名、人数、PAP 数量 / 类型、发放时间、签名）；更新失败不影响 PAP 发放。

常见问题：

- **发放按钮不见了**：确认行动状态是「进行中 / 已停止」，且 FC 是当前登录角色。
- **Character is not in a fleet**：角色当前不在舰队。
- **fleet does not exist / no access**：你不是 fleet boss（不能是 wing/squad commander）。
- **token 权限不足**：缺 fleet scope，需重新授权角色。
- **发错了**：小幅调整用行动审查（§4.4）；整批撤回可删除行动（同时清空该行动 PAP 与审查记录）。

### 4.4 行动审查与 PAP 奖惩调整

**日历 → 行动审查**，列出所有已发放 PAP 的行动。

列表列：行动标题、PAP 发放时间（精确到秒，UTC）、FC、单 PAP（tag 量化值）、人数、总额（含奖惩）。表头可排序，默认按发放时间倒序。**PAP 审查** 按钮仅对 `calendar.create` 用户显示。

审查弹窗显示每个成员的船型、星系、加入时间、当前 PAP、奖惩历史。旧行动的星系 / 加入时间可能显示「—」。

奖励 / 扣除流程：

1. 点 **绿色 +**（奖励）或 **红色 −**（扣除）
2. 填数量（正数）、理由（必填，≤255 字）；类型自动继承本次行动 tag 解析轴
3. 确认后成员 PAP 列实时更新，历史列追加一条记录

规则：

- 同一成员可多次调整，每次产生独立审计记录（金额、理由、操作人、时间）
- 调整实时回写 `paps.value`，所有统计页 / 军团排名 / 商店 API 自动同步
- 当前**可以扣到负数**（FC 自行把握纪律记账）；商店 API 用 `max(0, total)` 兜底
- 统计口径：普通行动被扣成负数时该负值作为惩罚计入「出勤 PAP」（见 [`02-整体计划.md`](02-整体计划.md)）
- 删除行动会同时清空该行动 PAP 与所有审查记录

权限：查看列表 / 明细 = `calendar.view`；奖惩 = `calendar.create`（不再要求是该行动 FC 本人）。后端强制校验权限与行动可见性。

## 5. PAP 统计与主角色聚合（概要）

成员在 **角色侧栏 → Paps** 看个人 PAP，军团管理在 **军团侧栏 → Paps** 看军团统计与排名。所有数据按 **主角色聚合**：

- 以 SeAT 用户的 main character 为汇总键，合并该用户全部 alt 的 PAP
- 军团排名默认展示主角色聚合结果
- API 返回的 `total_pap` 同样是主角色聚合后的结果

三个业务口径（出勤 PAP / 消费 PAP / 当前可用 PAP）的精确定义、恒等式与全局起始日设计，统一见 [`02-整体计划.md`](02-整体计划.md)。

## 6. PAP 商店对接协议

> 📘 **完整、最新、可直接发给外部项目的 API 文档见 [`06-API使用说明.md`](06-API使用说明.md)**（含余额查询 / debit / refund / JWT 跳转、统计时间范围与限流提示）。本节为概要，细节以 06 为准。

面向商店开发者，说明 SeAT PAP 插件与商店之间的完整交互。

### 6.1 架构与角色

```
浏览器 ──点击"PAP 商店"──> SeAT(seat-pap) ──302 + JWT──> 商店服务器
商店服务器 ──Bearer Token──> SeAT PAP API ──聚合后 PAP──> 商店
```

| 角色 | 职责 |
|------|------|
| SeAT (seat-pap) | 管理 PAP 数据、生成 JWT、提供 PAP API |
| 商店服务器 | 验证 JWT、管理会话、调用 API 查 PAP |
| 浏览器 | 用户操作、负责跳转 |

### 6.2 共享密钥

SeAT 与商店共享一个 **API Token**（设置页生成，48 字符随机串），两用途：

1. JWT 签名密钥（跳转认证）
2. API Bearer Token（商店调用查询接口）

管理员操作：**日历 → 设置 → PAP API 设置 → 生成 Token**，复制后配置到商店；在 **PAP 商店跳转设置** 填商店认证地址。需 `calendar.setup` 权限。

### 6.3 用户跳转（JWT 认证）

用户点侧边栏 **PAP 商店**（需 `calendar.view`），插件生成 JWT 并 302 重定向到 `商店认证地址?token=eyJ...`。

JWT = `Header.Payload.Signature`：

- **Header**：`{"alg":"HS256","typ":"JWT"}`
- **Payload**：

```json
{ "sub": 120, "main_character_id": 2118151113, "name": "Akina", "iat": 1711699200, "exp": 1711699320 }
```

| 字段 | 说明 |
|------|------|
| `sub` | **SeAT user_id** — 商店应以此为用户主键，永不变化 |
| `main_character_id` | 当前主角色 EVE id — 显示用，可能因切换主角色变化 |
| `name` | 当前主角色名 — 显示用 |
| `iat` / `exp` | 签发 / 过期时间（签发后 120 秒过期） |

- **Signature**：`HMAC-SHA256(base64url(header) + "." + base64url(payload), API_Token)`

> **务必用 `sub`(user_id) 做商店用户主键**，不要用 `main_character_id`：用户切换主角色后 character_id 会变，会被误判为新用户。`main_character_id` / `name` 仅显示，每次跳转更新。无论用哪个 alt 登录 SeAT，`user->id` / `main_character_id` 都相同，JWT 内容不受登录角色影响。

商店验证步骤：拆分 → 验签（HMAC-SHA256，constant-time 比较）→ 检查 `exp` → 按 `sub` 查找 / 创建本地用户、更新 `main_character_id`/`name` → 创建商店自有 session（时长自定，JWT 120 秒只约束跳转本身）。

验证示例（Python）：

```python
import hmac, hashlib, base64, json, time

def base64url_decode(s):
    s += '=' * (4 - len(s) % 4)
    return base64.urlsafe_b64decode(s)

def verify_jwt(token, secret):
    parts = token.split('.')
    if len(parts) != 3:
        return None
    signing_input = f"{parts[0]}.{parts[1]}".encode()
    expected = base64.urlsafe_b64encode(
        hmac.new(secret.encode(), signing_input, hashlib.sha256).digest()
    ).rstrip(b'=').decode()
    if not hmac.compare_digest(expected, parts[2]):
        return None
    payload = json.loads(base64url_decode(parts[1]))
    if payload.get('exp', 0) < time.time():
        return None
    return payload
```

PHP / Node 实现同理（`hash_hmac` + `hash_equals` / `crypto.createHmac(...).digest('base64url')`）。

### 6.4 PAP 查询 API

余额语义为「当前可用 PAP」。认证：`Authorization: Bearer <API_TOKEN>`（推荐）或 `?token=<API_TOKEN>`。

**单角色查询**：

```
GET /api/calendar/paps/{character_id}        # character_id 可为主角色或任意 alt，结果聚合到同一主角色
GET /api/calendar/paps/{character_id}?since=2026-03-01
```

成功 (200)：

```json
{
  "status": "success",
  "character_id": 2118151113,
  "user_id": 120,
  "total_pap": 3.0,
  "since": "2026-01-01",
  "sync_at": "2026-03-29 08:27:04"
}
```

| 字段 | 说明 |
|------|------|
| `character_id` | 主角色 ID（已聚合） |
| `user_id` | SeAT user_id（= JWT `sub`） |
| `total_pap` | `since` 起所有 alt 当前可用 PAP，`SUM(paps.value)` 聚合后做 `max(0, …)` 非负兜底 |
| `since` | 实际使用的起始日期 |
| `sync_at` | 查询时间 |

角色未找到返回 404。

**批量查询**（定时同步，单次最多 200 个）：

```
GET /api/calendar/paps?characters=2118151113,2118151114,2118151115
GET /api/calendar/paps?characters=...&since=2026-03-01
```

```json
{
  "status": "success",
  "data": [
    {"character_id": 2118151113, "user_id": 120, "total_pap": 3.0, "since": "2026-01-01"},
    {"character_id": 2118151114, "user_id": 121, "total_pap": 5.0, "since": "2026-01-01"}
  ],
  "not_found": [2118151115],
  "sync_at": "2026-03-29 02:00:04"
}
```

错误码：200 成功 / 400 缺 `characters` 或超 200 / 401 Token 错或缺 / 404 角色未找到 / 503 未配置 API Token。

聚合逻辑：按传入角色经 `refresh_tokens` 找到 SeAT 用户 → 取其全部关联角色 → 对 `kassie_calendar_paps` 中这些角色在 `since` 之后的 `value` 求和 → 返回主角色 ID + 聚合后可消费额度。

> **`total_pap` 语义**：对外可消费额度，口径上对应「当前可用 PAP」。每次奖惩 / 抽奖扣费 / 退款，`paps.value` 实时回写为「基础值 + Σ调整」，商店只需定期同步 `total_pap`。被扣到负数时已 `max(0, …)` 兜底。
>
> **breakdown（已实现）**：`since` 默认读全局 PAP 起始日并 clamp 为 `max(since, 起始日)`；查询带 `?breakdown=1` 时额外返回 `attendance_pap` / `consumed_pap` / `available_pap`，`total_pap` 保持兼容。详见 [`02-整体计划.md`](02-整体计划.md)。

### 6.5 对外部服务的要求

- **用户表以 `user_id` 做主键**（来自 JWT `sub`），不要用 `character_id`。
- 余额查询优先使用批量接口（每批 ≤200），不要高频轮询。
- 安全：HTTPS、Token 仅存服务端、必须验签（不能只解 payload）、必须检查 `exp`、签名用 constant-time 比较。
- 头像：`https://images.evetech.net/characters/{main_character_id}/portrait?size=128`（无需认证）。

### 6.6 抽奖开奖结算（settle）

抽奖不再购买时实时扣款。外部服务开奖后调用一次：

```http
POST /api/calendar/paps/lottery/settle
Authorization: Bearer <WRITE_TOKEN>
```

```json
{
  "ref_group": "lottery:3",
  "settled_by_character_id": 2118151113,
  "title": "第3期超网抽奖",
  "idempotency_key": "lottery-3-settle",
  "participants": [
    {"character_id": 2118151113, "amount": 10.00, "reason": "押注节点 #03, #07"}
  ]
}
```

SeAT 会创建一个抽奖 operation，写入负值 PAP 调整，并让该 operation 出现在行动审查页。纠错走现有 PAP 审查奖惩调整。

要点：

- `idempotency_key` 是整场结算幂等键，同 payload 重试不会重复扣。
- `ref_group` 是外部场次键；同 `ref_group` 不同 payload 返回 409。
- `character_id` 可传主角色或任意 alt，服务端归并到 main character。
- 余额不足不阻断，允许扣成负值；对外 `total_pap` 仍非负兜底。

### 6.7 商店预留：debit / refund

`POST /api/calendar/paps/debit` 与 `POST /api/calendar/paps/refund` 当前不用于抽奖，只保留给未来 PAP 商店恢复。

完整字段、错误码、幂等和限流说明见 [`06-API使用说明.md`](06-API使用说明.md)。
