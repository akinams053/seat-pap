## 4. 接手人必须知道的当前行为

- **开奖按钮何时出现**：售满（`sold_out`）显示「开奖」；`open` 且 ≥1 个已售节点时对 FC / 管理员显示「提前开奖」；一个都没卖出时不显示。
- **提前开奖语义**：`status=open` 且 `sold_count>0` 触发，只从已售节点抽，未售节点写 `voided_at` 作废，`draw_mode=early`。
- **整行动清零语义**：对当前 action 下每个 `paps.value != 0` 成员追加反向 `PapAdjustment` 冲正为 0，不删历史；已是 0 的跳过；未终态 lottery action（`open`/`sold_out`）会被后端拒绝。
- **抽奖消费即时进统计**：负数 `paps.value` 会即时进入角色 / 军团 PAP 统计，使统计混合出勤 / 消费 / 可用——这是阶段 7 要处理的已知现象，非缺陷。

## 6. 部署到测试服

本包通过 Packagist 安装 / 更新（分支与版本约束见仓库根 `README.md`）。测试服当前装的是完整版分支 `dev-docs/pap-hypernet-lottery-plan`。在 **SeAT 根目录** 执行更新：

```bash
cd /var/www/seat
sudo composer update akinams053/seat-pap --no-cache
sudo -u www-data php artisan view:clear
sudo -u www-data php artisan route:clear
sudo systemctl reload php8.4-fpm   # 服务名按宿主实际替换
```

按需追加：含 **migration** 跑 `php artisan migrate`；含**新增路由** 跑 `route:clear`（已在上）；含**静态资源（CSS/JS）** 跑 `vendor:publish --force --provider="Seat\Kassie\Calendar\CalendarServiceProvider"`。

> 阶段 7 各次更新多为 PHP / Blade / lang，一般只需 `composer update` + `view:clear`（+ 有新路由时 `route:clear`）。仅 `db01e62` 含一条清理 migration，需 `php artisan migrate`。
