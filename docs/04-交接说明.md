## 2. 已完成事项

### 2.1 抽奖外移

- 插件内旧抽奖 UI / controller / route 已退役。
- 侧边栏「超网抽奖」保留为外部跳转入口。
- 跳转 JWT 包含：`sub`、`main_character_id`、`name`、`balance`、`iat`、`exp`。
- 外部抽奖服务负责节点、购买、开奖、中奖记录。

### 2.2 settle 成行动

- 新增：`POST /api/calendar/paps/lottery/settle`。
- settle 会创建一个抽奖 operation：
  - `is_consumption = 1`
  - `consumption_key = lottery-settle:<hash>`
  - `user_id / fc_character_id = 开奖人所属 SeAT user / main character`
  - 自动绑定 `analytics=lottery`、`quantifier=0` 的保留 tag
- 每个参与者写负值 `PapAdjustment(source=lottery, ref_group=...)`。
- `Pap::recomputeValueFor()` 回写 `paps.value`。
- 同场幂等与冲突保护已验证。

### 2.3 行动审查

- 旧外部消费审查页已删除：`/calendar/audit/consumption` 返回 404。
- 行动审查列表显示：普通出勤行动 + 抽奖行动。
- 商店消费锚不显示在行动审查。
- 用户已在 Web UI 确认测试 operation 的 PAP 审查弹窗显示正确。

### 2.4 PAP 统计 / API

- 三口径仍成立：`出勤 PAP - 消费 PAP = 当前可用 PAP`。
- 消费判定以 `calendar_operations.is_consumption` 为准。
- 角色 / 军团 / API 仍按 main character 聚合 alt。
- `GET /api/calendar/paps/{alt}?breakdown=1` 已用测试样本验证：alt 正确归并到 main。

### 2.5 商店预留

- `POST /api/calendar/paps/debit`
- `POST /api/calendar/paps/refund`
- `ApiWriteTokenMiddleware`
- `Operation::standingFor()`

以上保留给未来 PAP 商店，当前抽奖不调用。旧的 `standingFor user_id=0` 外键问题已修复。

## 4. 已知验证摩擦点

### 4.1 API throttle

插件 API 已改用自有限流器 `calendar-api`（按 IP **300/min**，见 `CalendarServiceProvider::registerApiRateLimiter()`），替代原先继承宿主 `api` 组的 60/min。

判断：

- 正常抽奖 settle 是低频单次调用，远低于上限。
- 外部服务仍应防御性处理 429：读取 `Retry-After`，延迟重试。
- 如果未来余额查询被高频调用，建议用批量接口，并避免轮询。

### 4.2 测试数据

operation `181` 当前保留在测试服，会造成 `weier3` 对应 main character 的 `-0.03` PAP 消费。

是否清理由维护者决定。


测试服 target（服务器名 `test` = `ubuntu@ylxh.de:22`）：

```powershell
# Windows
E:\AI\All projects\ssh-gateway\scripts\ssh-gw.cmd test "<command>"
```

```bash
# mac / Git Bash
/Users/akina/project/ssh-gateway/scripts/ssh-gw test '<command>'
```

规约：

- 连接前说明目标是测试服 `test`（`ubuntu@ylxh.de:22`）。
- 只读命令可直接执行。
- 改动命令必须先确认并加 `--write`。
- 护栏会把部分 `php artisan` 只读命令误判为 mutating；若语义只读，可在确认后用 `--write` 绕过。
- 另有生产服 `prod`（`ubuntu@129.226.211.33:22`），改动门槛更高，能在 `test` 先验证的先验证。
